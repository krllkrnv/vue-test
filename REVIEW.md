# Ревью `review/ReviewMe.vue`

Компонент выглядит как поиск по товарам, но ломает односторонний поток данных Vue и сам себе портит исходный список.

## 1. Мутация props

В `updateQuery` пишется в `props.filters.query` и вызывается `props.products.push(...)`. Props в Vue односторонние. Такая запись может испортить состояние родителя, сломать реактивность и дать гонку, если тот же объект фильтров используют ещё где-то.

Как чинить: поле поиска вести через `emit('update:filters', ...)` или `v-model`. В массив родителя из дочернего компонента не пушить. Если временная строка нужна только внутри, держать её в локальном `ref`.

## 2. Два источника списка

Проп `products` объявлен, но для выдачи используется одноимённый `ref` с захардкоженными товарами. Имена совпадают, поэтому неочевидно, какой массив вообще живой. Проп почти не участвует в рендере, зато мутируется в обработчике.

Как чинить: либо список приходит сверху и локальная копия не нужна, либо компонент сам владеет данными и пропа нет. Назвать локальный массив иначе, например `catalog`. Исходник не перезаписывать.

## 3. Фильтр уничтожает данные

В `watch` результат кладётся обратно в `products.value`. После первого запроса из массива пропадают позиции, которые не совпали с текущей строкой. Следующий ввод уже ищет по обрезку, а не по полному каталогу. Если стереть запрос, исходный список сам не вернётся.

Как чинить: исходный массив не трогать. Отфильтрованную выдачу считать в `computed` или писать в отдельный `ref`, например `visibleProducts`.

## 4. Гонка по таймеру и мёртвый error

На каждый ввод ставится новый `setTimeout` со случайной задержкой. Предыдущий таймер не снимается, поэтому более поздний короткий запрос может проиграть более раннему длинному, и на экране окажется чужой результат. При размонтировании таймер тоже остаётся. При этом `error` объявлен, сбрасывается в `null`, но нигде не заполняется, так что ветка ошибки в шаблоне мёртвая.

Как чинить: хранить id таймера и делать `clearTimeout` перед новым запросом и в `onUnmounted`. Если это имитация API, ошибку реально выставлять в `catch` или в отдельной ветке мока. Пока идёт загрузка, не показывать предыдущую выдачу как будто она уже финальная, либо явно развести `v-if` / `v-else`.

## 5. Нет `:key` у списка

В `v-for` нет `:key`. Vue не может стабильно сопоставить узлы, при фильтрации будут лишние перерисовки и сюрпризы с состоянием DOM.

Как чинить: `:key="product.id"`. Для ключа не использовать индекс.

## 6. Логика в шаблоне

В шаблоне сразу `filter` по `available`, `sort` по цене и расчёт `(product.price * 1.2).toFixed(2)`. Это и тяжело читать, и гоняет работу на каждый ререндер. Число `1.2` нигде не названо: налог это, наценка или опечатка, из кода не видно.

Как чинить: вынести видимый список в `computed`. Сортировку делать на копии, не на исходнике. Цену считать в computed или в маленькой функции, коэффициент вынести в константу с понятным именем.

## 7. Побочные эффекты на каждый ввод

Кроме записи в props, каждый `@input` добавляет товар с `id: 999`. Повторные нажатия плодят дубликаты с одним и тем же id. Строка ещё и приводится к верхнему регистру, хотя фильтр ниже снова делает `toLowerCase()`.

Как чинить: из обработчика убрать `push` и `toUpperCase`. Оставить обновление строки поиска. Если нужен debounce, делать его вокруг запроса, а не вокруг порчи данных.

## 8. Поле без подписи и стили по тегам

У инпута только `placeholder`, без `label`. Для скринридера и для клика по подписи этого мало. В CSS стили висят на `input` и на `.item h3` / `.item p`, то есть на тегах, а не на классах блока. Так легко задеть чужую разметку, если компонент обрастёт вторым полем или другим заголовком.

Как чинить: видимый `label`, связанный с полем через `id` / `for`. Классы на сам инпут, заголовок карточки и описание, без селекторов тега.
